# Paper Pipeline

Workflow rules for drafting an academic paper end to end. These rules apply to every paper-writing session in this directory and any descendant project that imports them.

## Phase 0 — Idea elicitation

Before any tool call, ask the user for the paper's general idea in one or two sentences. Do not start writing without it. The idea drives every subsequent step.

After the idea is captured, ask which template to use:

1. **IEEE** (conference / transactions, `IEEEtran` class)
2. **MDPI** (open-access journals, MDPI class)
3. **EasyChair** (workshop / conference proceedings, `easychair` class)
4. **TSP** (Tech Science Press journals such as CMC, CMES, JCS, JIHPP, bundled `tsp.cls`)

Do not assume a default. Wait for the answer before copying any template files.

## Phase 1 — Reference discovery

Once the idea and template are fixed, search for relevant prior work using OpenAlex and Crossref. Do not invent citations. Do not pull from training data when an API call is possible.

Recommended endpoints:

- OpenAlex search: `https://api.openalex.org/works?search={url-encoded-phrase}&per-page=25&mailto={user_email}`
- OpenAlex DOI lookup: `https://api.openalex.org/works/doi:{doi}?mailto={user_email}`
- Crossref search: `https://api.crossref.org/works?query={url-encoded-phrase}&rows=25&mailto={user_email}`
- Crossref DOI lookup: `https://api.crossref.org/works/{doi}?mailto={user_email}`
- arXiv abstract page: `https://arxiv.org/abs/{arxiv_id}`

Both OpenAlex and Crossref are free and require no authentication. Adding `mailto={user_email}` puts the request in the polite pool with better rate limits. The user's email is recorded in `auto memory` (currently `vinceabella05@gmail.com`), or read from the `OPENALEX_API_KEY` / `CROSSREF_MAILTO` environment variable when running through `solo-referencing`. There is no API key for either service, the `mailto` parameter replaces it.

All references for one paper live in a single Markdown digest at `references/{paper-slug}.md`, where `{paper-slug}` is the paper's directory name under `papers-latex/` with any leading `{template}-latex_` prefix stripped. Examples:

- `papers-latex/easychair-latex_simbox-detection` → `references/simbox-detection.md`
- `papers-latex/tsp_survey` → `references/tsp_survey.md`

This keeps every reference for a paper in one place and matches the slug of the paired experiment directory at `experiments/{paper-slug}/`.

### File format

```markdown
# References, {paper-slug}

Source paper: `papers-latex/{dir}/`
Generated by `paper-pipeline/scripts/import_references.py` on YYYY-MM-DD.

Total cited keys: N. With abstracts: M. Without DOI: K.

---

## `{cite_key}`

- **Title:** ...
- **Authors:** ...
- **Year:** ...
- **Venue:** ...
- **DOI:** [10.x/y](https://doi.org/10.x/y)
- **arXiv:** ...
- **URL:** <...>

### Abstract

<verbatim abstract from OpenAlex when available, bib fallback otherwise>

### Notes

<optional reading notes, key claims, numbers, methods>

---
```

The `cite_key` follows the convention `lastnameFirstSignificantWordYear`, all lowercase, no spaces. Match the bib entry the paper will use.

### Generating

Use the importer to populate or refresh the digest from the paper's `.tex` and `.bib`:

```bash
python3 paper-pipeline/scripts/import_references.py paper-pipeline/papers-latex/{paper-dir}
```

The importer scans `\cite{}` keys in the `.tex`, fetches OpenAlex with `mailto={user_email}` for any entry that has a DOI, reconstructs abstracts from the inverted index, and writes a single Markdown digest. It overwrites the output file on each run, so long-form manual notes go in a sibling file like `references/{paper-slug}-notes.md` to survive refreshes.

## Phase 2 — Drafting

Always start with the introduction. The introduction crystallises the direction of the paper and constrains every later section. Do not skip ahead.

When the introduction is approved by the user, proceed to related work, then methodology, then results, then discussion, then conclusion, then abstract last.

Copy the chosen template from `paper-templates/{format}-latex/` into a new directory under `papers-latex/` named `{format}-latex_{short-paper-title}`, where `{short-paper-title}` is a kebab-case slug of three to five words. Do not edit files inside `paper-templates/` directly, those are pristine starting points.

Every paper has a paired experiment directory at `experiments/{short-paper-title}/`. The slug after the underscore in `papers-latex/...` must equal the experiment directory name exactly. When the paper cites a number, table, or figure, the result file producing it must live under that experiment's `results/` and be reproducible from its `src/`.

## Phase 2.5 — Figures

All figures live in `figures-drawio/` as `.drawio` source files. PNG / PDF exports go in the same directory beside their source. Do not generate figures elsewhere.

When asked to create or modify a figure, follow [figures-drawio/DESIGN_GUIDELINES.md](figures-drawio/DESIGN_GUIDELINES.md) without deviation. The guidelines cover:

- Canvas setup (`pageWidth`, `pageHeight`, grid size).
- Grid and spacing (every coordinate is a multiple of `10`, message slot pitch is always `50px`, taxonomy spacing is uniform `30px`).
- Sequence diagram message slot anatomy (label / arrow / subtitle layering, asymmetric inter-slot gaps).
- Tree and taxonomy spacing, text hierarchy, and connector routing.
- Signal and timing diagrams (slot grid, curved-edge waveforms, silence padding, alignment lines).
- Container fill colors paired with accent stroke colors, never invented hues.
- Element ID prefixes (`c_`, `s_`, `e_src_tgt`, `n_`, `l_`, `trunk_`, `t_`, `hdr_`, `icon_`, `signal_`).
- Typography tiers (lifeline label, section label, message label, subtitle).
- Mandatory legend box.

Before producing the XML, identify the diagram type (sequence, taxonomy, signal / timing, state, or generic flow) and read the corresponding section of the guidelines. Reuse colors, gaps, and prefixes from existing files in `figures-drawio/` when adding to the same family of figures so the visual style stays uniform across the paper.

The generated `.drawio` file must compile open without errors in the desktop draw.io app or the VS Code extension. After writing, list the file with `ls figures-drawio/` and report the file size as a sanity check.

## Phase 3 — Writing style

Apply [.cursor/rules/writing.mdc](.cursor/rules/writing.mdc) to every paragraph, sentence, and table cell written in the paper. Key rules:

- No semicolons. No em dashes.
- One idea per sentence.
- Define every abbreviation on first use in each section: `Full Term (ABBR)`. Only abbreviate terms used three or more times in a section, except field-standard abbreviations (3GPP, IEEE, LTE, 5G, RRC, NAS).
- Never start a sentence with an abbreviation.
- Article `a` vs `an` follows pronunciation, not spelling.
- No hyperbolic claims. Use hedging where evidence is partial.
- Cite specifically. Replace "research shows" with `[Author] (Year)` plus the actual citation.

## Phase 4 — Reference verification

Before any commit or submission, verify every cite key in the bib against OpenAlex or Crossref. Mismatches are common, especially for papers with similar titles or shared author surnames. Run the comparison strategy:

1. For each `\cite{key}` in the manuscript, find the bib entry.
2. If the bib entry has a DOI, fetch `https://api.openalex.org/works/doi:{doi}` and compare returned authors against the bib author list.
3. If only an arXiv id, fetch `https://arxiv.org/abs/{id}`.
4. For tool / spec citations (no DOI), confirm the URL is alive.
5. Flag any mismatch and ask the user before correcting.

## Phase 5 — Constraints

- Never fabricate URLs, DOIs, or citations.
- Never claim a paper supports a numeric result without quoting the abstract or paper.
- Match the prose attribution ("X et al.") to the bib entry's lead author. If the bib changes, update the prose.
- Keep the paper-templates directory unchanged across projects. New papers copy from it, never write back to it.
